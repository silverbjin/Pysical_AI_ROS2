# 12.1절 실행 가능한 실습 설계안

대상: https://github.com/silverbjin/Pysical_AI_ROS2 의 main, 기준 커밋 58fb5a0.

## 목적과 범위

본문의 생략된 초기화·물리 실행·관측·보상·종료 처리를 구현하여, 독자가 강화학습 환경의 한 에피소드를 직접 실행하고 상태·행동·보상을 확인하도록 한다. 정책 학습과 실물 로봇 배포는 이번 절의 범위에 포함하지 않는다. 무작위 행동 실험의 낙상은 정상적인 에피소드 종료로 처리한다.

## 구성 선택

1. **권장: Ch12에 독립적인 Python 패키지 추가.** MuJoCo 실습은 ROS 없이 Windows와 Linux에서 실행하고, Gazebo 비교 실습은 기존 Ch11 ROS 2 Jazzy/Gazebo Harmonic 패키지를 사용한다. 챕터별 디렉터리 구조에 맞고 기존 센서·SLAM 실습을 변경할 필요가 적다.
2. Ch11 패키지에 MuJoCo 환경을 직접 추가한다. 모델과 이름을 공유하기 쉽지만 11장에 12장의 의존성과 실행 항목이 섞인다.
3. Ch11 전체를 Ch12로 복제한다. 챕터가 독립적이지만 센서·SLAM 코드까지 중복되어 수정 유지 비용이 커진다.

## 권장안의 구현 규격

- `Ch12` 아래 설치 가능한 Python 패키지, 로봇 MJCF 모델, 실행 명령, 테스트, 한국어 Markdown 실습 가이드와 수정·검증 보고서를 둔다.
- 12개 관절 순서는 기존 모델과 동일하게 fr/fl/rr/rl, 각 다리의 hip/thigh/calf로 고정한다.
- 몸체 크기 0.60 × 0.30 × 0.15 m, 몸체 질량 6 kg, 허벅지와 종아리 길이 각각 0.25 m 등 기존 URDF의 주요 제원을 반영한다. 센서 등 생략 요소와 충돌 형상·관성의 차이는 문서에 명시한다. 엔진 간 동역학의 완전한 동등성을 주장하지 않는다.
- 기본 관측은 예제 호환 30차원: RPY 3 + 몸체 각속도 3 + 관절 위치 12 + 관절 속도 12.
- 선택 관측은 45차원: 기본 30 + 몸체 선속도 3 + 이전 행동 12. 각속도·선속도의 좌표계, RPY 단위, 관절 순서와 슬라이스를 문서화한다. 높이와 목표 속도 등 추가 상태가 빠진 입문용 관측의 한계도 설명한다.
- 행동은 float32 12차원 [-1, 1], 관절별 토크 한계에 비례하여 변환한다. 잘못된 크기나 비유한 입력은 오류로 처리하고 범위 초과 입력의 처리 정책을 명시한다.
- Gymnasium의 `reset(seed=...)`, `step`, `render`, `close` 규약을 구현한다. 낙상은 terminated, 에피소드 시간 제한은 truncated로 구분한다.
- 생존 보상, 목표 전진 속도 추종 보상, 에너지 및 행동 변화 패널티를 계산하고 항목별 수치를 info로 반환한다.
- 무작위 행동 및 간단한 자세 유지 제어로 상태·보상 흐름을 확인한다. 자세 유지 제어를 학습된 정책으로 표현하지 않는다.

## 검증 및 산출물

1. 실제 MuJoCo 엔진에서 모델 로드, 12개 actuator와 관절 매핑, 시드 재현성, 행동 제한, 보상, 낙상 종료와 시간 제한을 검사한다.
2. Gymnasium 환경 검사기와 여러 에피소드 실행을 통과하고, 가능한 환경에서 실제 렌더링도 확인한다.
3. 실제 Gazebo에서 기존 4족 모델을 실행하여 관절 상태·몸체 자세·시뮬레이션 시간 진행을 관측한다. 가능한 경우 기존 Ch11 회귀 검사를 함께 실행한다.
4. 실행 환경·명령·버전·결과를 증거 파일과 보고서에 기록한다. 실행 불가능한 항목은 미검증으로 표시하며 실제 실행 통과로 대체하지 않는다.
5. 검토 중 발견한 문제를 수정하고 필요한 검사를 다시 실행한 뒤 로컬 리포지토리에 커밋한다. 원격 push와 PR 생성은 별도 요청 없이 수행하지 않는다.

## 현재 환경에서 확인한 제약

- 작업 폴더 안 `work/Pysical_AI_ROS2`에 리포지토리 복제 완료.
- Python 3.11과 Git 사용 가능. MuJoCo와 Gymnasium은 아직 설치되지 않았다.
- Windows PATH에서 Gazebo 실행 파일을 찾지 못했다.
- WSL 배포판 조회가 `Wsl/EnumerateDistros/Service/E_ACCESSDENIED`로 실패했다.
- Docker CLI는 있으나 Docker 엔진에 연결할 수 없었다.
- Gazebo 실제 검증을 위해 사용 가능한 WSL 배포판 또는 SSH 환경 확인이 필요하다. 과거 Ch11 보고서의 성공 기록을 이번 변경의 실행 증거로 사용하지 않는다.

위 목록은 설계 작성 당시의 상태다. 이후 사용자가 Ubuntu-24.04 배포판을 지정했고, 권한이 있는 WSL 실행 경로에서 ROS 2 Jazzy·Gazebo 설치와 WSLg를 확인했다. 격리 가상환경에 MuJoCo·Gymnasium을 설치했으며, 실제 실행 결과는 [수정·검증 보고서](CHANGE_REPORT_KO.md)에 기록한다.
