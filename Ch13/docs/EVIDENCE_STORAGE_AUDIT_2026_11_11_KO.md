# 13.5 및 다른 절의 증거 용량 점검

2026-11-11 KST. 사용자의 요청으로 기존 보존 정책과 실제 폴더를 대조했다. 크기는 논리 파일 크기이며 파일시스템의 실제 여유 공간 변화와 다를 수 있다.

## 점검 결과

- Windows 작업트리의 13.5 원본 evidence 약 3.04GiB, 13.8 system 약 6.40GiB, 13.4 약 0.36GiB다. 4MiB 이상 파일의 같은 크기 후보를 SHA256으로 비교했으며, 서로 완전히 같은 별도 파일은 찾지 못했다. 분할 압축본 내부와 전개된 원본의 중복은 별도로 확인했다.
- 정책 도구를 실제 13.5 evidence 하위 루트에 대해 미리보기한 결과, Windows 측은 한 사례의 51,530,100바이트를 후보로 제시했다. 이 사례 `d50469aa`는 기존 힘 적용 원인 분석에서 참조하며 지정된 WSL 원본 경로도 현재 확인되지 않았다. 따라서 도구의 후보를 자동 승인하지 않고 보존했다.
- 별도 WSL 13.5 evidence는 약 18GiB였다. 정책 미리보기에서 삭제 후보는 0이었다. 약 4.5GiB·7.0GiB의 대표/보호 사례와, 각각 약 2.9GiB·443MiB의 종료 확인이 없거나 중단된 사례가 큰 비중을 차지한다. 특히 `e5f0aea4`는 기존 보고서가 명시한 종료 미확인 예외 보존 대상이고 `b7cedb29`도 teardown이 없다. 이들 원본은 유지했다.
- 13.2~13.4, 13.5 reuse, 13.6, 13.7, 13.8도 크기와 4MiB 이상 동일 파일을 비교했다. 사용자 자료나 현재 분석에 필요한 유일한 사례를 삭제할 근거는 찾지 못했다. 4MiB 미만 파일과 각 압축본 내부의 모든 조합까지 전수 중복 검사했다는 뜻은 아니다.

## 13.5에서 정리한 중복

`native-g2-mujoco-22afb6c3-a9da-4b77-ab32-ad8ec3fd1c65`의 `control_clock.jsonl`과 `native_command_trace.json` 전개 사본을 삭제했다. 각각 15,445,961바이트와 7,365,743바이트이며 합계 **22,811,704바이트**다. 원래 실행은 FAIL이었고 그 판단을 바꾸지 않았다.

이 사례의 보호된 전체 분할 ZIP 8개는 유지했다. 삭제 전 8개를 순서대로 연결한 전체 SHA256이 기존 checkpoint의 `aa5c1ba6698838effd427d07b799d0316ac5acb6432d1f3e52ec514d288569f6`과 일치했고, ZIP 내부 두 파일의 SHA256이 삭제 대상과 각각 일치했다. 경로·크기·해시는 [삭제 원장](../evidence/section_13_5/retention_duplicate_cleanup_20261111.json)에 있다. 체크포인트의 `originals_retained`는 생성 당시의 기록이며 전개 사본 제거 후에는 분할 원본 ZIP이 보존본이다.

두 파일을 빈 폴더에 실제 복원하고 크기·SHA256을 확인했다. 복원 도구는 원본 분할 ZIP의 전체 SHA256을 먼저 검증하고 기존 파일은 덮어쓰지 않는다.

```powershell
python Ch13/scripts/restore_13_5_split_evidence.py <이미 존재하는 빈 복원 폴더>
```

복원한 파일은 단일 분할본이 아니라 8개 모두가 필요하다. 복원 검증용 사본은 해시 확인 후 제거했다. 실험 결과·실패·source hash·다른 원본은 변경하지 않았다. 자동 삭제나 WSL 가상 디스크 축소는 실행하지 않았다.
