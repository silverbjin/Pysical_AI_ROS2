## 구현과 검증

criteria.py의 frozen dataclass와 읽기 전용 named policy를 사용했다. metrics.py의 기존 기본 호출은 book_v1의 원래 판정을 유지한다. 교육용 시간·위치는 성공 임무 집합으로 계산하고 CPU/기울기는 실패를 포함한 유효 표본으로 계산한다. 실패·미실행은 성공률 분모에서 빼지 않는다. 필수 성공 자료 누락·음수·NaN·중복 UUID·미회수 종료는 통과시키지 않는다. 집계는 정책 수치와 표본 집합/수를 출력한다.

새 batch prepare의 기본은 education_v1이며 v2 plan에 수치까지 고정한다. 이후 정책을 바꾸거나 다른 정책/물리 실패 trial을 섞으면 거절한다. 기존v1 plan은 book_v1로 유지한다. 단일 mission의 기본도 education_v1이고 criteria.json/trial metadata로 기록한다. 단일 trial의 success는 기존 실제 완료·물리·종료 판정이며, 성능 기준을 선택했다고 성공이 되지 않는다.

RED는 새 정책 API 부재1FAIL/3.90초였다. 계산을 구현한 뒤27PASS와 batch API 부재1FAIL/3.02초를 확인했다. batch 연결 후37PASS/CLI 플래그 부재2FAIL/4.26초였다. ## Level3 작업에 미치는 영향

이전처럼120초·3cm를 달성하기 위한 반복 성능 튜닝은 요구하지 않는다. 다만 마지막 Level3의 두 후보는 식탁 상판/link3 및 다리/link7 계획 충돌로 거절됐다. 완화한 시간·위치 수치로 이 충돌을 해결하거나 정상 완주로 재판정할 수 없다. 충돌·관측 권한·실제 파지와 안전 종료는 유지한다.

이번 변경만으로 새 engine이나10회 평가를 다시 실행할 이유는 없다. 다음 실제 개발 경계는 저장된 Level3 실패 경로의 충돌 원인을 독립적으로 조사하는 것이며, 세계 형상/충돌검사를 없애거나 이미 거절된 경로를 실행하지 않는다. 새로운 제어기·WBC·실기·학습은 범위에 추가하지 않는다.
