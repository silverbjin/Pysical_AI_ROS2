# 13.5 WSL 증거 추가 무손실 압축

작성일: 2026-11-11 KST. 사용자 추가 지시에 따라 이전 중복 제거 후 약 14 GiB였던 WSL evidence를 **약 2.4 GiB**로 줄였다. 앞선 중복 제거 전에는 약 18 GiB였다. `du -sh`는 반올림 값이다. 원래 성공·실패 판정이나 종료 기록은 변경하지 않았다.

이번 두 차례 압축에서 93개 사례의 161개 파일, **13,173,055,426 bytes**를 102개 ZIP, **1,594,922,150 bytes**로 대체했다. 논리 크기 기준 순감소는 **11,578,133,276 bytes**다. 이것은 앞선 중복 삭제 4,770,219,442 bytes와 별도 수치다. WSL 파일시스템의 가용 공간은 이번 압축 직전 939,148,296,192에서 최종 950,726,193,152 bytes로 늘었다. Windows의 가상 디스크 축소는 하지 않았다.

최신 G2 성공 `9cb8920c`의 7,442,440,927 bytes는 798,804,365 bytes ZIP으로 보존했다. 관측 종료가 확인되지 않았던 `e5f0aea4`의 원본도 새 ZIP에 보존했다. 이 보존은 그때의 FAIL이나 teardown 미확인 판정을 바꾸지 않는다. RUNNING으로 남은 `b7cedb29`도 마찬가지다. 결과·설정·출처·오류·종료 문서는 읽을 수 있는 위치에 그대로 남겼다.

각 원본을 압축하며 SHA256을 계산하고, 완성 ZIP에서 전체 압축을 풀어 SHA256과 ZIP CRC를 확인했다. 원본도 다시 읽어 SHA와 파일 정보를 확인한 뒤에만 삭제했다. 실행 중 열린 파일과 경로 이탈은 거부한다. 정리 후 102개 ZIP의 SHA를 재검증하고 파일별 원장을 모았다. 대표 사례의 일반 ZIP 5개 파일과 추가 ZIP 1개 파일은 별도 임시 폴더에 실제 복원하여 해시를 확인하고 임시 복원본을 제거했다. 전체 161개 파일은 삭제 전에 ZIP에서 모두 읽어 해시를 확인했지만, 별도 파일로 전부 다시 복원한 시험은 아니다.

## 자료 위치와 복원

- 사례별 ZIP과 `retained_raw_20261111.json`, `retained_raw_20261111_extra.json`은 해당 WSL 사례 폴더에 있다. ZIP 전체 및 개별 파일 해시는 저장소의 `Ch13/evidence/section_13_5/retention_wsl_compaction_20261111.json`에도 기록했다.
- 저장소 루트에서 `python3 Ch13/scripts/restore_13_5_compacted_evidence.py <WSL_사례_폴더> <기존_빈_복원_폴더>`를 실행한다. 추가 ZIP은 끝에 `--extra`를 붙인다. 두 ZIP은 각각 별도의 빈 폴더에 복원한다. ZIP 전체와 복원한 각 파일의 SHA를 검증하며 기존 파일에 덮어쓰지 않는다.
- `Ch13/scripts/compact_13_5_wsl_evidence.py`는 인수 없이 미리보기, `--phase2`로 추가 대상 미리보기다. 실제 처리는 `--apply`를 요구한다. 기존 ZIP이나 원장이 있는 사례를 덮어쓰지 않는다.
- 예전 분석기와 자동 보존 코드는 압축 파일 내부를 직접 읽지 못한다. 과거 원래 경로로 바로 읽던 분석은 먼저 복원해야 한다. 이번 작업은 과거 자료에 대한 수동 정리이며 신규 실행에 동일한 압축이 자동 적용된다는 뜻은 아니다.

남은 약 2.4 GiB에는 1.59 GB의 이번 보존 ZIP, 작은 결과·오류·출처 기록, 기존 샘플과 다른 소규모 자료가 포함된다. 잔여물 전체가 불필요하다고 볼 근거는 없어 추가 삭제하지 않았다. 전체 재생에 필요한 압축본은 단일 WSL 디스크에 있으므로 별도 백업은 이번에 확인하지 않았다.
