# 13.8 로그 보존 및 디스크 관리

2026-11-11 KST. 사용자의 디스크 관리 지시에 따라 기존 임무의 실패와 재현성을 보존하면서 중복 로그를 정리한다.

- 필수: 원본 판정·실패 원인·실행 조건과 UUID·소스/자산 동결 및 해시·실제 물리/종료/회수 증거·재현에 필요한 로그를 보존한다. 이전 실패를 성공 결과로 대체하지 않는다.
- 삭제 후보: 다른 필수 기록과 완전히 동일한 비추적 중복 로그, 재생성 가능한 일시 로그. 삭제 전에 실제 보존본과 각 파일의 SHA256, 경로와 Git 추적 상태를 확인하고 기록한다.
- 실패나 종료 원인을 보여 주는 유일한 로그, 사용자 자료, `sources/`, 이전 장의 원본과 동결 파일은 임의 삭제하지 않는다. 압축 파일의 해시만 확인하고 내부 원본 해시를 생략하지 않는다.
- 실행 중인 engine의 로그는 변경하지 않는다. 다음 실행에서 필요한 최소 기록과 보존 공간을 확인한다. 이 문서는 무인 주기 삭제를 설정하지 않는다.

## 2026-11-11 정리 기록

`batch_level23_20261105_c148d796/attempt_01.log`부터 `attempt_10.log`까지 10개, 합계 22,500,454바이트의 비추적 중복 원본을 삭제했다. 삭제 전에 `attempt_logs.tar.gz`의 SHA256과 manifest를 확인하고, 각 압축 내부 파일과 각 원본 파일의 SHA256이 모두 일치함을 검증했다. 압축본은 3,949,450바이트이며 기존 추적 manifest·판정·개별 사례 archive 및 source freeze는 보존했다. 당시 manifest의 `originals: preserved locally`는 archive 생성 당시의 기록이며, 이번 삭제 후 현재 상태는 이 문서가 갱신한다.

복원 예시: 해당 batch 디렉터리에서 `tar -xzf attempt_logs.tar.gz attempt_07.log`를 실행한 후 `attempt_logs_manifest.json`의 해당 SHA256과 대조한다. 기존 파일을 덮어쓰지 않도록 빈 디렉터리에서 복원하는 것을 권장한다.
