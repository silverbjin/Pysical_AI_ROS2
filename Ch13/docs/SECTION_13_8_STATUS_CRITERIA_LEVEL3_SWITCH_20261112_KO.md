# 진행 점검·기준 검토·Level 3 전환

작성일: 2026-11-12 KST. 사용자 지시: 반복 튜닝이면 Level 2 작업을 정지하고 Level 3로 넘어간다. 이 지시는 앞선 Level 2 완료까지 계속한다는 실행 순서를 대체한다. Level 2를 성공/인수 완료로 변경하는 지시는 아니다.

## 점검 결론

**Level 2 추가 튜닝과 재시도를 중단한다. Level 3의 기존 구현을 변경 없이 한 번 검증하는 단계로 전환한다.** v45~v51의 경로·초기화·관측 처리·Scan·목표 접근 보완은 각각 근거와 부품 시험이 있지만 연속 임무 성공으로 수렴하지 않았다. 반복 튜닝에 해당하며 더 이상 Level 2 숫자 조정으로 진행하지 않는다. 확정된 마지막 소스 v51을 보존하며 임의 되돌림도 하지 않는다.

원래 고정 평가 v28은 Level 2 0/5, Level 3 0/5, 합계0/10이다. 이후 선택 개발 사례를 이 분모에 섞지 않는다. 전체502 부품 PASS/73.97초와 공개 CI 성공은 구현 검증이며 실제 정상 완주/Owner 인수 증거는 아니다. 기능별 진척은 있으나 전체 완료율을 부품 통과율로 환산할 수 없다.

## Level 3 전환 명세와 제한

1. 마지막 Level2 실패의 source/archive/판정과 본 결정·기준표를 커밋한다. Level2 추가 코드·파라미터 변경·재실행은 하지 않는다.
2. 기존 v51의 미사용 사전 지정 Level3 UUID e475ece0-9f70-4dae-8de9-491ee92c95fc를 사용한다. 동일400파일/94자산,15Hz/overlap1/SE2=0/계측1이다. Level3는 기존NavFn+전진RPP/기존house·원통·접근·팔 경로다. Level2 전용 DUBIN·batch guard·보간 overlay가 적용되는 것처럼 기록하지 않는다. 기존 case_plan의 purpose 문구는 Level2 설명이므로 Level3 설명은 이 문서와 execution_profile을 우선한다.
3. 기존 공유lock/실제 소유 프로세스·설치/실행hash를 확인하고 단일engine으로 한 번 실행한다. 새 build/전역 설치/새WBC·정책·실기·인식은 추가하지 않는다. 기존502 부품 시험을 문서 변경 때문에 반복하지 않는다.
4. 문 통과→새RGB-D 관측→기존MoveIt 계획→파지·귀환·놓기의 실제 도달 단계, 최초 실패, 안전 중단, 종료를 기록한다. 실패하면 같은 세션에서 튜닝·재시도하지 않고 한계로 남긴다. 이 한 번은 정식10회 평가가 아니다.
5. 결과 보고서와 가이드의 현재 한계를 갱신해 커밋·게시/공개CI를 확인한다. 원고 목표 달성·추가 물리 witness·안전 상태를 분리해 보고한다. Level2/Level3 성공이나 Owner 인수를 대신 승인하지 않는다.

현재 결정은 도서 제공 범위를 넘는 반복 안정화 작업을 멈추고, 기존 Level3의 실제 상태를 확인하는 것이다. 추가 기준의 폐기나 원고 수치 변경은 이번 작업에 포함하지 않는다.
