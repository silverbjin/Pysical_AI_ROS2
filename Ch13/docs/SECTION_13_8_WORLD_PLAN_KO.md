# 13.8 원고 월드 확장 실행안

2026-11-05 KST. 사용자의 전체 원고 목표·추가 질문 없이 진행 지시 안에서 작성한 실행안이다. v15 개발 fixture의 성공을 원고 월드의 성공으로 옮겨 쓰지 않는다.

## 확인한 출발점

v15는 동일 engine의 연속 기능과 표시 파일 reader-lock 분리까지 실제1회 PASS했다. 귀환5.02cm/210.484sim초는 목표 미달이다. 이후 제어를 바꾸지 않은 자료 보존·복원 때문에 이 긴 실행을 반복하지 않는다.

원고 Level1은 캔이 바닥2m에 있어 기존0.5m 받침대와 다르다. 정적 위치 IK만으로는 파지 방향을 보증할 수 없었다. 설치 MoveIt2.12.4/TRAC-IK2.0.2의 실제 IK service와 독립 URDF FK로 기울어진 접근 후보를 확인했다. 최초 TF 누락·잘못 고른 양성 대조군·정수 timeout 사용도 원래 자료와 함께 보존했다. 알려진 테이블 자세의 양성 대조군과 비교한 뒤에만 후보라고 부른다.

현재 바닥 후보는 stand-off0.60m, 아래쪽30도 접근, 사전 거리0.06m다. 정적 렌더링에서 camera base-relative(0.4,0.4,0.29)m·yaw-40도·pitch down35도는 초기/사전/파지 시점의 원통 fit을 통과했다. 0.12m 사전 접근의 일부 IK 해는 몸통을 관통해 제외했다. 올바른 gripper joint8=-joint7 연동과 실제 관통/양의 접촉 margin을 구분해 다시 확인했다. 실제 정착 높이·경로·접촉·운반/놓기 검증은 남아 있다.

## Task4A: 원고 Level1을 먼저 연결

1. ROS에 의존하지 않는 불변 scenario 설정을 추가한다. 기본은 기존 development이며 이를 Level1로 자동 변경하지 않는다. target 좌표/수령 지점/지지면/카메라/접근 방향/거리/월드 기하와 scenario ID를 사례별 scenario.json으로 남긴다. 알 수 없는 ID는 시작 전에 거부한다.
2. 기존 scene/pick_scene에 opt-in hook만 둔다. Level1은 알려진 원통(2,0,0.04)m, 받침대 없음, 원래 floor 그대로다. 원본 로봇 질량/관성/정책/PD/그리퍼·시간 설정은 유지한다. 수령점은 기구학적으로 검토한 앞쪽 거리0.60m를 사용해 귀환 base(0,0,π) 기준(-0.60,0,0.04)m로 둔다.
3. 접근 후보 생성은 Level1에서0.60m stand-off로 제한하고 실제 RGB-D 점으로 Nav2 목표를 만든다. 바닥용 사전 접근0.06m·pitch down30도를 사용하며, 기존6D 계획·완전 Cartesian fraction·속도/가속도 검사를 그대로 통과해야 한다. 기본 개발/13.6/13.7의 수평 접근0.12m는 유지한다.
4. 내려놓기 목적 높이는 새 실제 원본 관측의 초기 높이를 유지한다. 받침대용 support 이름을 바닥에 억지로 복제해 겹치는 물리 지지면을 만들지 않는다. floor contact의 실제 힘과 새 관측의 수령 영역을 별도로 검사한다. target freejoint는 여전히 사후 판정 전용이다.
5. 파지·운반 판정은 scenario의 수령 좌표/높이를 명시적으로 소비한다. manifest·profile·source와 다른 사례를 집계하지 않는다. 원고 Level1과 development를 다른 ID로 남긴다.

## 부품 및 실제 검증

- 먼저 scenario 기본값 보존/잘못된 ID/좌표·height·그리퍼 연동과 floor support 조건의 실패 시험을 쓴다.
- 알려진 원통의 초기·접근·파지 정적 시야와 충돌을 시험한다. 위치 truth는 fit 뒤의 평가에만 쓴다.
- 새 분리 build·source/94자산 동결·native 사본·공유 lock·새UUID로 Level1 실제 사례를 순차 실행한다. 기존 개발 성공을 다시 돌려 대신하지 않는다.
- 실패 시 source/설정/원본과 실제 원인을 남긴다. 관측 수명·접촉·행동 회수 기준을 늘려 통과시키지 않는다.

## Task4B 이후

공통(3,1) 테이블, 박스/5도 경사, 좁은 문/식탁 아래를 같은 scenario 인터페이스로 연결한다. 원래 원고에 구체 치수가 없는 형상은 선택 치수를 공개하고, 원본 정책의 통과/도달 가능성을 필요한 최소 사례로 확인한다. 초기 시야에 없는 대상은 카메라 health와 대상 부재를 구분하고 소유된 사전 탐색 이동 뒤 실제3D 관측을 얻어야 한다.

팔/적재물의 실제 외형과 장애물 높이를 확인한 뒤 costmap을 구성한다. 높이가 다른 받침대·테이블을 무조건 전체2D 투영해 통과 불능으로 만들지 않는다. 공식 Nav2 footprint 갱신의 존재는 물리 통과 증거가 아니다.

원고3cm 목표에는 기존 Nav2의0.06m goal tolerance가 충분하지 않다. 설치1.3.13의 SimpleGoalChecker 구현과 실제 정착 오차를 확인했으며, 정밀도 변경은 별도 opt-in과 영향 navigation 회귀로 확인한다. 120초 목표를 맞추기 위해 기존 팔 한도를 늘리지 않는다.

기능 인수 후 고정 source/scenario/설정의10개 UUID 슬롯을 먼저 정하고 평가한다. 누락·중복·실패·불완전 자료도 분모와 FAIL 판정에 남긴다. 개발 버전별 실패/성공을 고정10회 평가로 섞지 않는다. 마지막으로 원고 소절별 가이드·분석 출력·배포/복원·단일 작업자 검토를 마무리한다.
