## 2. G1과 C1이 함께 반복된 이유

**G1은 새로운 실행의 출발 상태를 만드는 선행 게이트였다.** C1은 센서·팔 수납·기립·교정과 정착을 통과한 실제 모델에서 수행된다. 실패 후 정상 종료한 엔진을 다시 시작하면 이전 G1의 물리 상태가 남지 않는다. 새 소스가 이 선행 조건을 깨지 않았는지도 확인해야 한다. 따라서 새 C1 앞의 G1 자체는 무의미한 중복이 아니다. 실패한 엔진 상태를 재활성화하거나 오래된 관측으로 이를 생략하는 것은 해결책이 아니다.

**C1은 여러 층의 결함을 순서대로 드러냈다.** 수치 반복·비선형 IK·부동소수점 경계·수신과 적용 시점·현재 관측의 실행 가능성은 서로 다른 문제다. 실제 실패 입력을 보존하고 오프라인 재현으로 고친 부분은 유효한 디버깅이었다. 그 수정이 실제 물리 성공까지 의미하지는 않는다.

그러나 최신 세 실행은 이미 비슷한 물리 진행 한계에 도달했다.

## 3. 튜닝 반복인가

| 구분 | 판단 |
|---|---|
| Kp·토크·기한을 바꿔 성공하는 조합을 찾는 전형적인 튜닝 | 최신 세 실행은 이에 해당하지 않음. 원래 한계가 유지됨 |
| 수치 표현·수신 수명·정확한 IK 제약의 결함 수정 | 재현 가능한 소프트웨어 디버깅 |
| G1 복귀 곡선 등 후보를 실제로 비교하고 실패 시 복원 | 일부 경험적 조정 시험에 해당 |
| 힘 응답 모델 검증 없이 주변 로직 수정 후 같은 통합 시험 반복 | 넓은 의미에서 증상에 따른 시행착오에 해당. 계속하면 사실상 튜닝 루프가 됨 |

따라서 “튜닝은 전혀 없었다”도, “모든 작업이 무작위 튜닝이었다”도 부정확하다. 문제는 변경 횟수 자체보다 **각 재실행 전에 무엇이 입증됐고, 그 실행이 어떤 가설을 구별할 것인지가 충분했는가**다.

## 4. 새로 확인한 물리적 원인 후보

이번 채팅의 독립 최소 시험은 이미 종료했고 작은 결과를 보존했다.

- 자유 관절: 관성0.1kg·m², 1Nm, 2ms에서100step 매번 쓰면 Δqd=2.0rad/s, 매5step만 쓰면0.4rad/s였다. 명령 소비·재기록 의미는 계산과 일치했다.
- 구면 접촉: 같은1Nm를 매2ms 써도 관성0.01kg·m²에서 감쇠0일 때 전달 렌치1Nm, 기존 calf 감쇠10.95445일 때 약0.313393Nm였다. 접촉력도 같은 비율로 바뀌었고 최종 속도는 거의0이었다. 감쇠0은 판별 대조군이며 로봇에 적용한 설정이 아니다.
- 실제 실패267 모델: 전체 관성행렬을 사용한 정상 순가속도 가정의 명령 예측은 FL calf −30.00096Nm, 기록된 native 명령은−30Nm였다. 다리12관절의 최대 오차는 기존 연속 정역학 식22.61547Nm에서0.00413Nm로 줄었다.

이는 명령 자체가 누락된다는 설명보다 **암시적 감쇠와 접촉 충격량을 처리하는 이산 물리와 상위 모델의 불일치**를 강하게 지지한다. 다만 실제 대조에는6ms 시각 차이가 있고 가속도·속도 편향을 완전히 설명한 것은 아니다. 모든 C1 실패를 이것 하나로 설명했다고 선언하지 않는다.

더 중요한 미완료 항목이 있다. **한 상태의 명령을 맞춘 식은 `위치 명령 변화→접촉력 변화`의 미분 관계를 검증한 것이 아니다.** 이 관계가 틀리면 수치 최적화가 맞아도 실제 하중은 예상한 방향·크기로 이동하지 않는다. 다음 수정은 이 검증을 통과한 뒤 결정해야 한다.

## 5. 공식 구현·논문 조사 결과

**DART의 계산 순서.** 설치 환경과 대조한 공개6.13.2 구현은 자유 동역학·속도 적분 다음 접촉 제약과 충격량을 처리한다. 암시적 관성에는 시간 간격에 비례한 감쇠가 더해진다. 따라서 정지 후 속도가 작다는 사실만으로 감쇠 효과도 작다고 판단할 수 없다. 위 최소 시험은 이 계산의 영향을 독립적으로 재현했다. [World::step](https://github.com/dartsim/dart/blob/v6.13.2/dart/simulation/World.cpp#L156), [GenericJoint](https://github.com/dartsim/dart/blob/v6.13.2/dart/dynamics/detail/GenericJoint.hpp#L1773)

**관측량의 의미.** Gazebo DART의 전달 렌치는 자식 body의 힘을 joint frame으로 변환한 값이다. 명령 토크·관절 전달 렌치·최종 속도는 같은 관측량이 아니다. 오래된 공식 이슈에도 joint-force 조회와 역동역학 계산 시점의 문제가 논의돼 있지만, 이를 현재 설치 버전의 동일 버그 증명이나 패치 지시로 사용하지 않는다. [현재 gz-physics 코드](https://github.com/gazebosim/gz-physics/blob/gz-physics7/dartsim/src/JointFeatures.cc#L712), [공식 이슈124](https://github.com/gazebosim/gz-physics/issues/124)

**SEIKO의 직접적 교훈.** 위치 제어로 접촉력을 조절하려면 전신 유연성에 따른 힘 응답을 모델링하고, 계획된 힘과 실제 피드백 사이를 제어해야 한다. 논문은 이 응답의 미분 관계와 실행 가능성의 중요성을 보여 준다. 동시에 모델 오차로 접촉 전환이 실패할 수 있다고 명시하므로 SEIKO를 참고했다는 사실만으로 현재 구현이 검증되지는 않는다. TALOS의500Hz/2kHz 설정이나 토크 피드백을 그대로 이식하지 않는다. [저자 논문](https://arxiv.org/html/2312.16465v4), [고정 커밋 구현](https://github.com/hucebot/seiko_controller_code/blob/972e3a69af9334eec324e61566433fabf05bf061/inria_model/src/SEIKOController.cpp#L637)

**Improved Feasible Region의 교훈.** 다음 발을 들기 전에 남을 세 지지발의 구동·관절 실행 가능성을 보고 몸체 목표를 정한다. 현재의 국소 QP infeasible을 반복 한도 증가로 해결하려고 해서는 안 된다. 정확한 actuator 모델을 반영한 뒤에도 현재 지지 자세에서 다음 하중 상태가 불가능하면, 하중 해제 전에 몸체 목표를 다시 계획해야 한다. [TRO 논문 VI-A](https://arxiv.org/html/2011.07967v2#S6.SS1)

## 6. 권고하는 해결 순서와 재시험 조건

1. **물리 모델 일치 검증:** 전체M·감쇠·접촉의 관계를 확인한다. 질량 없는 프레임의 파서 기본 관성, 좌표계, 샘플 위상을 먼저 맞춘다. 단일 배율을 맞추는 방식은 쓰지 않는다.
2. **힘 응답 검증:** 작은 접촉 부품에서 사전에 정한 미소 위치 입력에 대한 힘 변화의 방향·크기·다른 지지점과의 결합을 독립 비교한다. 식을 만든 표본 외의 자세·하중에서도 확인한다. 실제 로봇이 필요하면 G1 뒤 별도 유계 부품 진단으로 수행하며 C1/G2 성공으로 세지 않는다.
3. **다음 지지 상태 검증:** 수정된 모델에서도 실제 명령20/30Nm·관절·마찰·기하·이동 한계 안에서 다음 세 발 지지가 가능한지 평가한다. 불가능하면 body-shift 계획 문제로 돌린다. 이미 infeasible해진 실패267을 억지로 PASS시키지 않는다.
4. **최소 수정과 회귀:** 검증된 힘 응답만 명시적 Gazebo G2 경로에 반영한다. 현재 관측 사용·수신 수명·실제2N/100ms 해제 판정·정상 종료·원래10ms/32회 등은 유지한다. 반영 전 실패 회귀를 정의하고 계산 비용도 확인한다.
5. **통합 복귀:** 위 단계의 근거가 갖춰지면 고정 소스로 G1→C1을 실행한다. 다시 같은 물리 실패가 나오면 같은 실행을 반복하지 않고 예측과 실측이 처음 갈라진 지점으로 돌아간다. 최종 연속 성공 횟수는 실패를 포함한 원래 기준으로 센다.

추천은 현재 물리를 보존한 모델·계획 수정이다. 감쇠 제거·게인 변경·엔진 교체는 다른 물리를 만드는 대안이며 현재 해결책으로 채택하지 않는다. 전체 WBC 교체도 아직 필요한 근거가 없다.

## 7. 현재 상태

원인 판별은 진전됐지만 힘 응답 미분 관계의 검증과 런타임 수정은 남았다. C1 네 발 완료·전체G2·양 엔진 연속 성공·Nav2·최종 회귀·commit/push는 완료되지 않았다. 이번 분석에서 성공을 추가로 세거나 기존 실패를 제외하지 않았다.
